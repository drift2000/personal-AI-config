# 0004 — Новини: власне розширення ocStore; сторінки Joomla → oc_information

Status: accepted
Date: 2026-10-27

## Context

У ocStore 3.0.5.1 немає блогу/новин (лише oc_information без дат і списків; в адмінці uk-ua лежать мовні файли blog/* від мовного пакета — коду немає). Новини на старому сайті — каталог ZOO «Новини» (109 записів типу news: «Коротка новина» + «Повна новина», дата, перегляди; одна категорія, коментарів немає). «Статті» (#__content, 48) — фактично статичні сторінки магазину (Про нас і підсторінки, Контакти, Доставка, Вакансії, виробники…), одна справжня стаття в «Публікації і статті».

Розглянуто: сторонній модуль блогу (готові категорії/теги/коментарі, але чужий код, ризик PHP 8.3 / ionCube, OCMOD-правки, чужа схема) і новини в oc_information (без дат/списку).

## Decision

- Новини — власне мале розширення `extension/module/news` (як product_tab/price_request: події, без змін ядра): таблиці oc_news, oc_news_description (title, short_description, description, meta_*), oc_news_to_store; список /news із пагінацією, сторінка /news/<keyword>, CRUD у Каталог → Новини, посилання у футері. Рішення користувача.
- ЧПУ: ключ `news_id=N` у oc_seo_url; ядро передає невідомий query як route («news_id5» після санітизації роутера) → подія `catalog/controller/*/before` підміняє route на extension/module/news/info; посилання — власний rewrite (Url::addRewrite).
- Сторінки Joomla → oc_information; ключ = alias пункту меню header (старі багатосегментні адреси pro-nas/... відкриваються, бо декодер ядра розбирає посегментно); перший рівень меню → футер; порядок з меню. Демо-сторінки ocStore не змінюються.

## Consequences

- Таблиці зберігаються при видаленні модуля; міграція створює їх сама, якщо модуль ще не встановлено.
- Немає категорій/тегів/модуля «Останні новини» — додавати окремо за потреби.
- «Опитування» (item 7545 іншого типу в каталозі новин) не переноситься.
