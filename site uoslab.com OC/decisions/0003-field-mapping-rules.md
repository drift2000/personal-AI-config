# 0003 — Мапінг полів JBZoo → ocStore за правилами + вкладки товару

Status: accepted
Date: 2026-10-26

## Context

Свіжий аудит UA-магазину: 1339 унікальних назв полів з даними, 1057 з них — лише в одному типі, 653 заповнені в ≤5 товарах. Ручне рішення по кожному полю неможливе. Опис товару в JBZoo розбитий на textarea-секції.

## Decision

Правила (за типом елемента та назвою), а не рішення по кожному полю:
- `jbimage` (Фото, Главное фото) → `oc_product.image` + `oc_product_image`.
- textarea «Опис/Описание/Повна новина» → `oc_product_description.description`.
- textarea-секції «Переваги/Преимущества/Перевага», «Використання/Использование/Застосування», «Опції/Опции», «Завантаження/Загрузки» → **окремі вкладки** (власне розширення, `oc_product_tab`); секції-заглушки (лише заголовок) пропускаються; PDF з `download/` копіюються, посилання переписуються.
- `checkbox/select/radio` (21 поле) → атрибут + фільтр, підписи — з конфігу типу.
- Решта `text` → атрибути; дублікати назв (одиниці, регістр, RU/UA) зводяться за словником синонімів, який погоджує користувач.
- `relateditems` → `oc_product_related`.
- Неопубліковані товари (504) → переносяться зі `status = 0`.
- Коментарі ZOO (5282, схвалених 0) → не переносяться.
- Значення у видалених з конфігу полях (72 значення, 31 товар, усі неопубліковані) → не переносяться (запропоновано, остаточне рішення користувача — після перегляду `orphan_values.csv`).

Вкладки — власне мале розширення (не сторонній модуль): таблиця `oc_product_tab` (product_id, language_id, title, content, sort_order), редагування в адмінці й вивід у темі через OCMOD, без змін ядра.

## Consequences

- Вручну погоджуються лише ~20 ключових полів і словник синонімів атрибутів.
- Розширення вкладок має бути встановлене до імпорту товарів.
- Кількість атрибутів після зведення — сотні; атрибутні групи — за розділом каталогу.
