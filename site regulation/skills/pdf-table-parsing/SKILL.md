# Парсинг таблиць із PDF

Постановка для DEA CSA — `briefs/2026-06-04-dea-csa-pdf-parser.md` у приватному каталозі проєкту. Інструменти й стан звірено 2026-10-29; частина файлів станом на цю дату не закомічена — перевірити `git status`.

## Інструменти в `src/core/`

Запуск усередині контейнера: `./run.sh dev exec backend python core/<script>.py ...`.

| Файл | Призначення |
|---|---|
| `inspect_pdf_objects.py <pdf> --pages N..` | вивести rect/fill-об'єкти з кольорами — чи є фон рядків векторними об'єктами |
| `detect_row_bands.py <pdf> --pages N.. [--zoom --threshold --min-band-height]` | растеризувати сторінку й знайти смуги фону рядків (y-інтервали в координатах PDF) |
| `highlight_pdf.py in.pdf out.pdf --pattern REGEX` | підсвітити рядки, що збігаються з regex, для візуальної перевірки |
| `pdf_table_parser.py <pdf> [-o json] [--log] [--pages]` | загальний парсер: смуги → рядки, заголовок → колонки, склеювання багаторядкових клітинок, синоніми |
| `test_pdf_parse.py [--pdf --out --log --pages]` | runner для `pdf_table_parser` (це не тест) |
| `us_dea_csa.py` | окремий парсер DEA: межі таблиці за чорними лініями, рядок прив'язано до CSCN, колонки за лівими краями слів заголовка; пише `/app/tmp/dea_csa_v1.rows.json` і `.debug.txt` |

Робоча команда `import_us_dea_csa` має власний простіший парсер із фіксованими межами x-колонок. Перед змінами вирішити, який із трьох підходів розвивати, і не плодити четвертий.

## Порядок роботи

1. Розвідка: `inspect_pdf_objects` і `detect_row_bands` на 2–3 сторінках. Визначити, що надійно задає межі рядків: фон, лінії чи якір-колонка (наприклад, CSCN).
2. Колонки — за позиціями слів заголовка на кожній сторінці, а не фіксованими x, якщо макет може змінитись.
3. Склеювання багаторядкових клітинок: перенос усередині слова склеювати без пробілу, між словами — з одним пробілом.
4. Синоніми: усе після першої назви (тригери `" ("` і `"; "`, включно з `;` усередині дужок) перенести в OTHER NAMES.
5. Вивід: JSON рядків із `_page`/`_row` для трасування + детальний лог по сторінках/рядках, щоб знайти місце помилки. Тимчасові результати — у `/app/tmp` (`src/tmp/`, не комітити).
6. Перевірка: кількість рядків проти джерела; ручна звірка першої/останньої сторінки й рядків із переносами та дужками; `highlight_pdf` для сумнівних випадків.
7. Лише після цього підключати парсер до management command (skill `regulation-import`). Парсер має лишатися чистою функцією `pdf_path → list[dict]`.
