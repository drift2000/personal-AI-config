# PostgreSQL, MySQL, MariaDB — зміни схеми й даних

- Визначити СУБД і версію проєкту; синтаксис має відповідати їй (MariaDB ≠ MySQL 8 у JSON, CTE, window-функціях різних версій).
- Будь-яка зміна схеми: міграція в механізмі проєкту + план відкату. Деструктивні операції (`DROP`, `TRUNCATE`, видалення колонок, масові `UPDATE/DELETE` без `WHERE`) — лише з явного погодження.
- Великі таблиці: оцінити блокування (`ALTER` у MySQL/MariaDB, `CREATE INDEX CONCURRENTLY` у PostgreSQL).
- Кодування та collation визначаються вимогами й поточним станом бази даних конкретного проєкту. Не змінюй їх без аналізу сумісності, впливу на дані та окремого погодження.
- Не виконувати запити на production/спільних БД; для діагностики — локальна копія або знеособлені дані.
- Дампи не додавати до Git (ні робочого, ні приватного).
